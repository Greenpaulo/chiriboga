# L9.1 Unpriceable breakers

**Roadmap item:** L9.1 · **Depends on:** L9.0 · **Sets:** playable sets (`documentation/card-sets.md`)
**Read first:** `documentation/ai-principles.md`, `documentation/corp-ai/principles.md`, [L9 Run-simulation fidelity](L9-run-simulation-fidelity.md), [L9.0 Lockout honesty](../../backlog/code-review/L9.0-lockout-honesty.md)
**Verified against code:** 25942f4 (2026-10-09)

## Goal
L9's limit 1, split out so that I2 can depend on it alone: a matching
breaker whose price the evaluator cannot read must never make a server look
secure, create a lockout or add a made-up finite break cost. I2 scores ICE
by the change in lockout and mandatory break cost; without this, an
unpriceable breaker makes every stronger ICE look like a lockout.

## Current behaviour
Verified at `25942f4` (after L9.0):

1. `_breakerActivationCost()` prices a breaker by replacing
   `rc.ImplementIcebreaker` on a Corp-owned calculator and calling the
   breaker's `AIImplementBreaker`. If the hook never calls
   `rc.ImplementIcebreaker`, the result stays `Infinity`. Without the hook it
   reads `cardText`; with no pump pattern and a positive strength gap it
   returns `Infinity`, unless `breaker.AIBreaksRegardlessOfStrength` is set.
2. `_icePlanOutcome()` turns an `Infinity` mandatory layer into
   `hasHardLockout` with the reason "has mandatory breaks with no capable
   breaker", which is wrong here: a capable breaker is installed.
3. In the playable sets only Sang Kancil and Principia (`elevation`) are
   unpriceable Runner icebreakers (no `AIImplementBreaker`, no `cardText`).
   They are the bug
   [`sang-kancil-and-principia-priced-as-unbreakable.md`](../../bugs/sang-kancil-and-principia-priced-as-unbreakable.md),
   which gives them proper hooks. After that bug is fixed, this item changes
   no playable-set evaluation; it guards future and in-progress sets
   (`vantagepoint`) and hook mistakes.
4. L9.0's honest verdict has the same gap. `_honestLayerOptions()` sets
   `noBreaker` only when no breaker matches, so a layer whose matching breaker
   is unpriced has no options and becomes `honestLockout` with the honest
   reason "<ICE> cannot be passed" only when no alternative option is available.
   An ICE-owned `AIBreakCost` covering the required subroutines supplies a
   native `click-break` option even when the installed breaker is unpriced;
   that layer does not create an honest lockout (click-budget feasibility is
   evaluated separately).

## Design
- `_breakerActivationCost()` reports whether it priced the breaker
  (`{cost, priced}` internally; callers that need a number keep one).
- Before the probe, consult `AIBreakCost(iceCard, subroutineCount, server)`
  on the installed Runner breaker, returning `{credits, clicks, counters}`.
  This extends L9.0's implemented `AIBreakCost` hook to breaker-owned
  mechanisms that do not go through `ImplementIcebreaker`. It supplies that
  breaker's price, not the price of an ICE's native click-break ability.
- L9.0's ICE-owned `AIBreakCost` prices the ICE's native self-break ability
  with linear `{credits, clicks}` costs (see `documentation/ai.md`); it did
  not introduce the originally proposed `AIClickBreakable`. The honest
  evaluator consults the ICE's hook for that native option and the installed
  breaker's hook for the breaker option, under the remaining click budget.
  When both mechanisms apply, compare legal native, breaker and mixed routes,
  choosing the cheapest feasible route under the shared resource budgets.
  Each broken subroutine is charged once, through the mechanism used. Neither
  owner's hook overrides the other; if the breaker remains unpriced, a priced native
  route is an upper bound, not proof of the unknown cheapest cost, and the
  unpriced-breaker contract below still applies.
- A matching breaker that is still unpriced is treated as able to get
  through: that layer contributes no hard lockout and no finite mandatory
  cost, the server is not secure on that layer's account, and `reasons`
  records "unpriced breaker <title>". The result also carries
  `unpricedBreakers` (titles) so I2 can skip or discount a candidate whose
  delta depends on an unknown price.
- An unpriced layer is an exception to L9.0's finite honest-cost guarantee.
  Neither `honestMandatoryBreakCost` nor `honestBreakCost` is required to be
  finite when its total depends on that layer. The unknown-cost representation
  is chosen at implementation planning; `unpricedBreakers` must distinguish
  unknown totals from priced totals, and consumers must not coerce an unknown
  cost to zero, invent a finite fallback, or subtract it as a numeric delta.
  Other, priced layers can still establish security or a lockout independently.
- Applies to today's fields and to L9.0's honest fields alike: it is a
  correctness fix to "no capable breaker", not a new verdict.
- No numeric fallback. One may replace the reachable treatment later only
  with tests proving it is a lower bound on actual cost for every breaker it
  covers (L9's rule).

## Safety and information boundary
- Only installed, public Runner cards. Never Grip or Stack identities.
- Evaluation stays read-only and inside the existing hypothetical guards; a
  throwing hook is treated as unpriced.

## Test scenarios
1. A Runner with 30 credits and a matching breaker that has neither
   `AIImplementBreaker` nor `cardText`, against a stronger ETR ICE: not
   secure, no hard lockout, reason names the breaker.
2. The same with an `AIImplementBreaker` that never calls
   `rc.ImplementIcebreaker`.
3. A breaker declaring `AIBreakCost` is priced from the hook; a server it can
   afford is not secure and one it cannot afford is.
4. A throwing `AIBreakCost` or `AIImplementBreaker` is unpriced and leaves
   credits, counters and run state unchanged.
5. With no matching breaker at all, today's lockout and reason are unchanged.
6. Changing hidden Grip or Stack cards changes nothing.
7. An installed matching unpriced breaker is the only obstacle: both verdicts
   are non-locking and insecure, `unpricedBreakers` names the breaker, and no
   finite honest cost is fabricated. Adding a priced layer preserves its
   independently justified security while totals depending on the unpriced
   layer remain marked unknown.
8. A click-breakable ICE and an installed breaker declaring `AIBreakCost`:
   assert the honest route uses the cheaper feasible native, breaker or mixed
   option without double charging, including when clicks are insufficient for
   a full native break. With the breaker unpriced, preserve `unpricedBreakers`
   and the unknown-cost contract even when a native route is priced.
