# I2.1 Empty-Archives reward valuation

**Roadmap item:** I2.1 · **Depends on:** I2, F4 · **Sets:** playable sets (`documentation/card-sets.md`)
**Read first:** `documentation/ai-principles.md`, `documentation/corp-ai/principles.md`, [install decisions design note](install-decisions-design.md) (disabled-policy owners)
**Verified against code:** 343b2be (2026-10-16)

## Goal

Decide when an empty Archives (no agenda, no HQ backdoor) is worth an ICE
layer because a successful run on it gives the Runner something other than
agenda points: public run-success rewards on Runner cards (credits, draws,
counters, tags removed) and pressure that feeds central-run economies. Today
this is an explicit gap: I2 keeps the empty-Archives exclusion, and the
recovered `emptyArchivesRunPressure` option (default off) admits Archives on
observed run pressure without valuing what those runs give.

## Current behaviour

`_nothingWorthProtecting()` excludes an empty Archives without an HQ backdoor
unless `emptyArchivesRunPressure` is on and `_serverRunPressure()` reports a
positive penalty. I2's ranking (option `iceMarginalSecurity`) reads only that
exclusion: a valueless Archives earns stake 0 from `_breachConsequence()`, so
even when admitted it never outranks a server with agenda stake. See
[architecture: install planning today](../architecture.md#install-planning-today).

## Design

To be refined when raised. The direction: a credit-equivalent value per
successful empty-Archives run from public Runner cards (a card hook such as
`AIRunSuccessReward(server)` on the Runner cards that pay on central or
Archives runs, documented in `documentation/ai.md`), multiplied by I2's
Archives breach hazard, entering I2's score as a separate bounded component
beside `riskReduction`. The exclusion is lifted only through that component,
never by restoring `emptyArchivesRunPressure` as a gate. Audit the playable
sets for Runner cards whose run-success effects are Archives-relevant before
choosing the hook shape.

## Safety and information boundary

Only installed, public Runner cards and the Runner's public history may feed
the reward; never the Grip or Stack. The Corp's own Archives contents are
known to it.

## Test scenarios

1. An empty Archives with no public run reward stays excluded.
2. A public Runner card that pays on a successful Archives run makes an ICE
   layer on Archives score above zero, bounded by its declared reward.
3. Hidden Grip substitution changes no candidate.
4. With the option off, decisions are identical to I2's.

## Acceptance gate
F4 gate. Option `emptyArchivesRewardValuation` (Corp AI), off in the baseline
and on in the candidate, with `iceMarginalSecurity` on in both arms (or at
its adopted default). Committed deck pool, paired seeds, 200 games per deck
pair, bootstrap 95% intervals.
Collectors: `successfulRunsByServer`, `strandedUnrezzedIceCost`.
Starts: none.

| Check | Metric | Better | Threshold |
|---|---|---|---|
| Improve | `successfulRunsByServer.archives` | lower | interval of the improvement above 0 |
| Guard | `winRate` | higher | regression at most 0.02 |
| Guard | `pointsStolen` | lower | regression at most 0.2 |
| Guard | `strandedUnrezzedIceCost.credits` | lower | regression at most 1 |

Gate command: `node scripts/ai-batch.js gate --corp-option emptyArchivesRewardValuation=true --corp-option iceMarginalSecurity=true --collector successfulRunsByServer --collector strandedUnrezzedIceCost --improve successfulRunsByServer.archives --guard winRate=0.02 --guard pointsStolen=0.2 --guard strandedUnrezzedIceCost.credits=1`
