# L9.0.1 Adopt honest lockout

**Roadmap item:** L9.0.1 · **Depends on:** L9.0, F4 · **Sets:** none
**Read first:** `documentation/ai-principles.md`, `documentation/corp-ai/principles.md`, [L9.0 Lockout honesty](L9.0-lockout-honesty.md)
**Verified against code:** 3c25455 (2026-10-09)

## Goal
Let the Corp's existing decisions use L9.0's honest security verdict instead
of today's, so a server protected only by "the Runner has no breaker
installed yet" or by click-breakable bioroids is no longer treated as safe
for scoring, rezzing and protection. This changes many decisions at once (L7.1
showed that a more accurate shared signal can still make play worse), so it is
gated.

## Current behaviour
After L9.0, `_evaluateServerSecurity()` returns both today's verdict
(`isSecure`, `hasHardLockout`, `totalMandatoryBreakCost`) and the honest one
(`honestIsSecure`, `honestLockout`, `honestMandatoryBreakCost`). Every
consumer reads today's: `_protectionScore()`, `_rankedServersToProtect()`,
`_iceLayerPolicy()`, the `_centralBreachLossRisk()` early return,
`_isAScoringServer()`, the rez checks in `_iceSecurityWithAndWithout()`, and
the draw and purge checks. See
[architecture: server security evaluation](../architecture.md#server-security-evaluation).

## Design
- Option `honestLockout` (Corp AI, default off). When on, the evaluator's
  `isSecure`, `hasHardLockout` and `totalMandatoryBreakCost` take the honest
  values, so every consumer switches together. Switching consumers one at a
  time is a fallback if the gate fails (the L7.1 analysis split by consumer
  to find its cause).
- No consumer logic changes; only which verdict they read.

## Safety and information boundary
- Inherits L9.0's: public information only.
- With the option off, every decision and F4 per-game hash is unchanged.

## Test scenarios
1. With `secureScoringServerGate` on and an agenda installed in the remote's
   root, a remote whose only ICE is a rezzed Eli 1.0, against a Runner with
   clicks and no breakers: with the option on it is not a scoring server
   (`_isAScoringServer()` rejects it at the secure-gate check); with it off it
   is (it passes the gate and returns true at the root agenda check). Without
   the gate, or without an agenda, scoring upgrade or ambush in the root, the
   result goes through the protection-score comparison instead and this
   scenario does not isolate the verdict.
2. With the option on, a central protected only by a "no breaker yet" layer is
   ranked for protection as insecure, and the logged reason says why.
3. With the option off, all decision fixtures and snapshots are unchanged.

## Acceptance gate
F4 gate. Option `honestLockout` (Corp AI), off in the baseline and on in the
candidate. Committed deck pool, paired seeds, 200 games per deck pair,
bootstrap 95% intervals.
Collectors: `securityCalibration` (built by L9.0; reported, not gated).
Starts: none.

| Check | Metric | Better | Threshold |
|---|---|---|---|
| Improve | `pointsStolen` | lower | interval of the improvement above 0 |
| Guard | `winRate` | higher | regression at most 0.02 |
| Guard | `pointsScored` | higher | regression at most 0.2 |
| Guard | `gameLength` | lower | regression at most 1.5 |

Gate command: `node scripts/ai-batch.js gate --corp-option honestLockout=true
--collector securityCalibration --improve pointsStolen --guard winRate=0.02
--guard pointsScored=0.2 --guard gameLength=1.5`

## Things to consider
- `gameLength` is guarded because a more cautious Corp may stall: fewer remote
  scores and more ICE installs.
- If the gate fails, follow "When a gate fails", then split by consumer as the
  L7.1 analysis did before proposing a narrower option.
- The pool is `core-v1`; check that its Corp decks include bioroids and that
  its Runner decks start without full rigs, otherwise the gate never reaches
  the change (the `--quick` run's changed-game count shows this).

## Acceptance criteria
- [ ] Every test scenario above is covered by a deterministic test that asserts the logged reason as well as the choice.
- [ ] The behaviour change ships behind an AI option that defaults to off (named in the Resolution).
- [ ] The gate is ready to run: every collector and start board it names exists and is tested, and a `--quick` run of each gate command completes and reports at least one game changed by the options.
- [ ] Applicable gate evidence is recorded in the Resolution.
      For F4: exact command, committed deck pairs, paired seeds, seed count,
      every metric's baseline/candidate result and bootstrap 95% confidence
      interval, guarded-regression result, pass conditions and thresholds; an
      improvement interval's lower bound must be above zero. Only then is the
      option switched on by default.
- [ ] `documentation/corp-ai/architecture.md` describes the new behaviour.
- [ ] `node tests/run-all-tests.js` passes.
