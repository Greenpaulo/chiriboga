# R1.2 LEO sacrifice in the last paid-ability window

**Roadmap item:** R1.2 · **Depends on:** F4, R1.1 · **Sets:** elevation (LEO Construction: Labor Solutions, Bumi 1.0, Mercia B4LL4RD); systemgateway (Manegarm Skunkworks, Anoetic Void)
**Read first:** `documentation/ai-principles.md`, `documentation/corp-ai/principles.md`, `documentation/corp-ai/specs/reactive-commitment-design.md`
**Verified against code:** 376f32c (2026-09-25)

## Goal
Hold LEO Construction's identity ability through a run until the Runner has
passed the last ICE, then use it only when ending the run there is worth a
bioroid, counting the Corp's approach-server triggers that would still fire
on that server. The LEO Glacier precon relies on this: the ICE and upgrades
tax the Runner first, and the sacrifice forces a re-run.

## Current behaviour
- LEO's ability is a paid ability in `abilities[]` (`sets/elevation.js`),
  offered through the `trigger` command in every run paid-ability window
  (Run 2.1, 3.1, 4.3, 4.5). It is not an approach-server trigger: the engine's
  last paid-ability window before approach is Run 4.5 (`runResponseBeforeApproach`),
  reached after passing the innermost ICE (or directly, for a server with no
  ICE); then Run 4.6.1 and the Run 4.6.2 `responseOnApproachServer` triggers
  fire, followed by Run 5.1 with no paid-ability window between.
- The Corp AI never consults LEO's `AIWouldTrigger()` in live play and picks
  the bioroid by index; see the bug ticket
  [leo-construction-ability-chosen-without-consulting-ai-hook.md](../../bugs/leo-construction-ability-chosen-without-consulting-ai-hook.md).
- `AIWouldTrigger()` fires for an agenda in the root, a central with a
  bioroid costing 3 or less, or any bioroid costing 2 or less, and declines
  when `_evaluateServerSecurity()` already reports the server secure. It
  ignores which window it is asked in and whether a later approach trigger
  (Manegarm Skunkworks, Anoetic Void) would end the run anyway.
- In the LEO Glacier precon (2 Manegarm Skunkworks, 1 Anoetic Void, 3 Bumi 1.0,
  3 Mercia B4LL4RD) the two clash: a LEO sacrifice at Run 4.5 pre-empts
  Manegarm's tax and Void's end-the-run.

## Design
- **Step 1: the bug fix.** The bug ticket above must be fixed (its
  reproductions passing in the green suite) before this item starts; this item
  relies on the run window handlers asking the card before choosing
  `trigger`, and on the preferred bioroid being honoured.
- **Hold record.** LEO's `AIReservedValue(context)` (R1.1's hook) returns a
  `"run"` record while a run is in progress on a server where the ability is
  offered and the Runner has not yet reached the last Run 4.5 window (reason:
  waiting for the last ICE). Its `expiryCondition` is true when the run ends or
  the ability has been used this turn. While the record is active, the window
  handlers do not use the ability.
- **Decision at the last Run 4.5 window** (`Phase_Movement()` with
  `approachIce < 1`, after its own upgrade rezzes). LEO fires only when the
  value of ending the run now exceeds the chosen bioroid's value, where:
  - the stakes come from public state the Corp already evaluates (agendas in
    the root, central stakes as in `_serverHasStakes()`);
  - the bioroid's value is its rez cost plus any declared defensive value,
    and the cheapest is chosen, as the existing hook computes;
  - **approach triggers still to come** are counted: for each rezzed root card
    of the attacked server that declares the new hook
    `AIApproachWouldEndRun(server) -> boolean` ("given public state, this
    card's approach-server trigger will end the run whatever the Runner
    chooses") and returns true, LEO holds (reason names the card). Manegarm
    Skunkworks returns true when the Runner can neither spend two clicks nor
    pay 5 credits; Anoetic Void returns true when its `Enumerate` would offer
    it and its `AIWouldTrigger()` is true. A tax the Runner can pay is counted
    as a tax, not an end of run: LEO compares ending the run now against the
    tax plus the access the Runner would get.
  - The existing "already secure" guard (keep a Brân lock) stays.
- **Tactical override.** When the breach would let the Runner win (an agenda
  in the root reaching their winning total) and no approach trigger will
  certainly end the run, LEO fires regardless of the value comparison.
- This is the one cross-window consideration the design note allows: LEO at
  Run 4.5 reads the declared outcome of Run 4.6.2 triggers; it never reorders
  or suppresses them (that is R2).
- Behind the Corp AI option from R1.1, default off.

## Safety and information boundary
- Reads only public state: Runner clicks and credits, rezzed Corp cards, the
  Corp's own hand and board. Never assumes the Runner's hidden cards or
  whether they will jack out.
- `AIApproachWouldEndRun()` must be deterministic and read-only, and return
  true only when the end of the run does not depend on a Runner choice.
- Once-per-turn only: LEO is not held back from one run for a later run in the
  same turn (design note non-goal).

## Test scenarios
1. Remote with an agenda, two rezzed ICE (Bumi 1.0 outermost): at Run 2.1,
   Run 3.1 and the Run 4.5 window after the outer ICE, the Corp does not use
   LEO (reason: waiting for the last ICE); at the last Run 4.5 window it uses
   LEO and trashes the cheaper bioroid.
2. No run in progress, or LEO already used this turn: no record and no
   trigger.
3. Last Run 4.5 window; the server also holds a rezzed Anoetic Void whose
   hook would fire, the Corp has 2 credits and at least 2 other HQ cards: LEO
   holds, reason names Anoetic Void.
4. Rezzed Manegarm Skunkworks, Runner with 1 click and 4 credits: LEO holds
   (Manegarm will end the run). With 3 clicks and 10 credits and an agenda in
   the root: LEO fires.
5. Rezzed Manegarm Skunkworks, Runner able to pay, no agenda in the root and
   only low central stakes: LEO holds and lets Manegarm tax; the reason gives
   both values.
6. The attacked server is already secure per `_evaluateServerSecurity()`:
   LEO holds, as today.
7. Breach would win the game for the Runner and the Runner can pay
   Manegarm's tax: LEO fires (tactical override).
8. Scenarios 1 to 7 give identical decisions under two different Runner
   Grip/Stack substitutions of equal size.

## Acceptance gate
Gated. Baseline: the code after the bug fix, option off. Deck pairs from F4's
committed pool: LEO Glacier as Corp against at least three Runner precons,
400 games per pair (the effect is per run, so small per game), paired seeds.

- Improvement: `pointsStolenByServer` (remote) per game; the interval of the
  reduction has its lower bound above zero.
- Guards: `winRate` no drop beyond 2 percentage points; `pointsStolen` no
  increase beyond 0.1 per game; `decisionLatencyMs` no increase beyond 10%.
- Collectors added: `leoSacrifices` (per game) and
  `leoSacrificesPreemptingCertainEnd` (sacrifices made when a rezzed root card
  declared `AIApproachWouldEndRun()` true); the latter must be 0 in the
  candidate.

## Things to consider
- F4's deck pool must include LEO Glacier as a Corp deck; if it does not,
  adding it is this item's first gate step.
- Manegarm's Runner-side AI pays clicks first unless the Runner has more than
  9 credits; the tax's value to the Corp depends on which, so value it from
  public clicks and credits rather than from that AI's policy.
- Whether a bioroid ICE the Runner has already passed is worth less than one
  still to be encountered in later runs is a calibration question for the gate.
