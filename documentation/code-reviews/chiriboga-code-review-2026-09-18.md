## What these commits do

Two separate threads of work, landed back-to-back:

1. **`0df0a79` — Deckbuilder generalisation.** Random deck generation (`DeckBuild()` in `utility.js`) previously only ever drew from a hardcoded `sg`/`su21`/`ms` card pool, even when a table had the Eternal format loaded with every set enabled — a limitation the README had explicitly documented. This commit adds a generic, set-aware path (`DeckBuildFromAllowedSets`, `DeckBuildCollectSetCards`, `DeckBuildChooseAgendas`, etc.) driven by a new `deckBuildAllowedSetCodes` global that `decklauncher.php` populates from whatever sets are actually loaded at the table. `gauntlet.php`/`engine.php` are untouched (they never set the new global, so `DeckBuild` falls through to the original legacy branch).
2. **`9be247c` → `387ec49` — Vantage Point set implementation.** Registers a new card set (`vp`, ids 36000–36999) as `hidden`/`untested`, then implements the first ~13 of its 66 cards across three batches, alongside small, targeted engine extensions in `phase.js`/`mechanics.js` that new cards needed: a pre-approach redirect phase (`runWouldApproachServer` / `responseOnWouldApproachServer`), an Archives-breach face-up hook (`automaticOnArchivesCardsTurnedFaceUp`), a per-subroutine hook (`automaticOnSubroutineResolved`), and a fix so `Trash()` still invokes its `afterTrashing` callback when zero cards were trashed. `1ba30c0` and `ed51e87` are pure documentation commits describing the card-implementation backlog and the workflow (including runbooks for coding-agent batches) used to drive this work.

## Strengths

- **The deckbuilder fix is real and matches a documented, known limitation** — the README's "Known Limitations" section describing exactly this problem is deleted in the same commit that fixes it, and the new `deckbuild-format-pool.test.js` explicitly exercises "every identity legal in every declared custom-game format," not just the identity used for manual testing.
- **`CountInfluence` got a genuine, independent bugfix bundled in.** Agenda card definitions in `sets/*.js` deliberately carry no `influence` property (agendas are influence-free by rule). The *old* `CountInfluence` didn't special-case agendas, so `ret += cardSet[cardNumber].influence` on an off-faction agenda would have added `undefined` and poisoned the whole influence total with `NaN`. It likely never manifested because the old fixed sg/su21/ms flow always forced a specific neutral agenda (see below), but the new code closes the hole properly by skipping agenda cards and guarding with `isFinite()`.
- **The Professor's influence-free-first-copy-of-each-program rule is correctly scoped** — it only exempts `program` cards, keyed by title, and only for that specific identity, so it can't accidentally leak into other identities' influence counting.
- **Legacy behaviour is preserved for callers that don't opt in.** `gauntlet.php`/`engine.php` never set `deckBuildAllowedSetCodes`, and `DeckBuild()`'s new parameter defaults straight back through to that global, so the new code path is opt-in and doesn't change output for those consumers except where noted below.
- **The Vantage Point engine extensions are purpose-built, not speculative.** Each new hook exists because a specific shipped card needs it, and I could trace each one to its consumer: `runWouldApproachServer`/`responseOnWouldApproachServer` back Baker's HQ/R&D redirect off an Archives run (correctly placed *before* the approach phase so its trigger list gets rebuilt for the new destination server); `automaticOnArchivesCardsTurnedFaceUp` backs Nurse Hạnh's "2+ facedown Archives cards turned faceup → draw 2"; `automaticOnSubroutineResolved` backs Take a Dive's "did a subroutine resolve during this run" check.
- **The `Trash()` fix matches its own documented contract.** The docstring says `afterTrashing` is "called after trashing is complete with parameter cardsTrashed" — that was never true when 0 cards were trashed before this change. Fixing it to match the doc is correct, not scope creep, even though it's a shared function with ~100+ call sites across the codebase.
- **`scaffold_set.py`'s `PACK_MAP` fix is a genuine correction**, not just tidying: `tai`/`rwr` pointed at file-name strings (`theautomatainitiative`, `rebellionwithoutrehearsal`) that don't match the real files (`sets/automatainitiative.js`, `sets/rebellion.js`, per `config.js`'s own registry comment) — the old mapping would have generated stubs pointing at nonexistent files.

## Issues / things worth a second look

1. **The legacy agenda-injection removal changes behaviour for `gauntlet.php`/`engine.php`, not just the new decklauncher path — worth calling out explicitly in the PR/commit description.** `DeckBuildRandomAgendas` (still the only agenda-picker for the legacy, non-allowed-sets branch of `DeckBuild`) previously force-included card `30069` ("Send a Message") in every corp deck it built. This commit removes that special case entirely, and the new test suite explicitly asserts the legacy helper "must also respect its supplied pool instead of injecting Send a Message or any other hardcoded agenda" — so this looks deliberate and is arguably a rules-accuracy fix (there's no real Netrunner rule requiring a specific named agenda). But it's a behaviour change for *every* caller of that shared function, including ones unrelated to the "use all legal sets" feature the commit is titled for, and nothing in the commit message flags it. Recommend calling it out explicitly next time so it doesn't read as an accidental side effect during a later bisect.
2. **`automaticOnSubroutineResolved` fires before the subroutine's own effect resolves, despite the name.** In `phase.js`, the new `AutomaticTriggers("automaticOnSubroutineResolved", ...)` call sits *immediately before* `Trigger(params.card, params.ability, ...)` — i.e. before the subroutine text actually executes — inside `phases.runSubroutines.Resolve.trigger`. For the one card that currently uses it (Take a Dive, which just needs to know *that* a subroutine fired, not its outcome) this is harmless. But the name promises "resolved" (past tense/after-the-fact), and a future card hook that inspects post-effect state (e.g. "the Runner just took damage from that subroutine") would get stale state if implemented against this hook as named. Either rename it to reflect "about to resolve," or move the call to fire after `Trigger()` if that's achievable given the pseudophase caveat already noted in the surrounding comment — worth a decision either way rather than leaving the name and behaviour mismatched.
3. **No dedicated regression test for the `Trash()` empty-array callback fix**, despite it being a widely-shared engine function (100+ call sites across `mechanics.js`, `phase.js`, `ai_runner.js`, and every set file). The fix is correct and low-risk (the full suite still passes), but a two-line unit test asserting `Trash([], false, cb)` invokes `cb` would make that guarantee explicit and catch a future regression, rather than relying on it only being exercised incidentally by whichever Vantage Point card needs it.
4. **The deckbuilder's "curated economy/draw" card lists are hardcoded by numeric ID and won't pick up new sets automatically.** `DeckBuildFromAllowedSets` fills a chunk of each generated deck from fixed lists like `[30007, 30018, ..., 33005]` for runner economy and `[30037, 30048, ..., 31082]` for corp economy — spanning several existing sets but, naturally, none of Vantage Point's ids (36000+), since those cards didn't exist yet at commit time. That's not a bug in this commit, but it means Vantage Point's own economy/draw cards will only ever get picked up via the generic catch-all `nonAgenda` fill at the end rather than the "quality-weighted" curated pools — worth a follow-up note (maybe in the new integration guide) so this list doesn't quietly go stale as more sets land.
5. **Minor:** `DeckBuildChooseAgendas`'s retry loop is bounded by a fixed 100 attempts rather than the existing `deckBuildingMaxTime` wall-clock budget used elsewhere in the file (`DeckBuildRandomAgendas`, `DeckBuildRandomly`). Not a correctness issue — each attempt is cheap and bounded — but it's an inconsistent throttling convention within the same file, worth aligning if it's ever revisited.

Nothing above broke a test, and I didn't find any undefined-function references, off-by-one errors, or unhandled-exception paths in the new engine code.

## Bottom line

Solid day's work across two unrelated fronts. The deckbuilder change closes a real, previously-documented gap and comes with a test that actually proves it (reconstructing the expected pool independently rather than just running the generator and eyeballing the size). The Vantage Point engine extensions are narrowly scoped to what the shipped cards need, and I confirmed by removing the one failing (asset-only) assertion that the new cards' actual behaviour is fully covered and passing. The findings above are a naming/timing nit on one new hook, a test-coverage gap on the `Trash()` fix, and two things worth flagging in commit messages/docs rather than code — no correctness bugs found.
